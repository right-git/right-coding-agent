# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Install dependencies: `uv sync` (uv is the environment manager; torch/torchvision come from the pytorch-cu128 index on Windows)
- Run the agent REPL: `uv run python -m src.main`
  - Requires a `.env` at the repo root with `ENV`, `LLM_API_KEY`, `LLM_API_BASE`. Importing `src.config.settings` fails without them, so tests and scripts that touch `src.config` also need it.
- Lint + format: `bash lint.sh` — black (120 columns, configured in `[tool.black]`) then flake8 over `src/`, `evaluation/`, `tests/`; run it before finishing a change.
- Run all tests: `uv run python -m unittest discover -s tests`
- Run one test file: `uv run python -m unittest tests.test_computer_use`
- Run one test: `uv run python -m unittest tests.test_computer_use.ClassName.test_name`

pytest is **not** installed — the test suite is `unittest`-based (the README's pytest command does not work). Each test file prepends the repo root to `sys.path` itself, so discovery works from the repo root without packaging. The whole suite runs in a few seconds; nothing in it touches the real desktop, network, or GPU.

Logging goes to `logs.log` via loguru (`src/config/logging.py`); stdout logging is off by default, so check that file when debugging runtime behavior.

## Architecture

This is an async coding-assistant agent built on LangChain, with a desktop computer-use capability driven by a local vision model.

### Chat loop and LLM layer

`src/main.py` runs the terminal chat REPL (`src/ui/chat.py`, prompt-toolkit + rich). It holds the LangChain message history across turns and calls `Agents.right_coding_agent()` once per user turn. On errors it rolls the history back, and it always passes history through `trim_incomplete_tool_calls` (`src/llm/utils.py`) so a turn that died mid-tool-call doesn't leave a dangling tool-call block that would make the next API call invalid. Providers (notably Gemini via OpenRouter) occasionally end a turn with an empty completion — no text, no tool calls, zero usage — which the agent loop reads as a final answer; `process_user_turn` detects this (`is_empty_final_response`), drops the empty message, and retries once with `EMPTY_RESPONSE_NUDGE`, warning the user if it happens twice.

Finished turns are **compacted** before entering history: `process_user_turn` returns `finalize_turn_history(trimmed_messages)` (`src/llm/history.py`) — `compact_finished_turn` followed by `prune_images`, which collapses the turn's tool tail — all AI-tool-call/ToolMessage pairs — into one synthetic `run_tools` pair (merged scripts as the call, capped at 2k chars; counts plus trimmed non-noise result heads as the output; `search_tools` results survive only as counters, while `get_tool` contracts are carried in the recap verbatim, capped at 6k chars — dropping them made the model re-run search_tools/get_tool every turn, two extra full-context round-trips; keeping them self-regulates, since a turn that skips get_tool adds no contracts section). Inside a running turn the model still sees everything in full — only the persisted history shrinks; earlier turns (and their recaps, flagged `tool_recap` in `additional_kwargs`) are never rewritten, so provider prompt caching keeps its stable prefix. Recap messages carry explicit ids so the next turn's usage accounting excludes them. `prune_images` then stubs out old images — every image in history is re-sent on every model call, so only the newest tool screenshot (`KEEP_TOOL_IMAGES=1`) and the newest user-pasted images (`KEEP_USER_IMAGES=3`) survive; older `image_url` blocks become `[screenshot/image removed to save context]` text stubs (separate budgets, spent newest-first; rewritten messages keep their ids; idempotent). Pruning rewrites an old message once when its image ages out — a one-time prompt-cache break per expiring image, cheaper than re-sending it forever.

Turns are **cancellable**: both agent calls go through `ChatUI.run_cancellable`, which races the turn task against an `EscapeWatcher` (`src/ui/interrupt.py`) — a thread draining raw console keys via msvcrt (Windows-only; `create()` returns None elsewhere and the turn just runs). Esc cancels the asyncio task (aborting the HTTP call) and raises `TurnCancelled`, which `process_user_turn` catches before the generic handler: history rolls back to `base_messages`, buffered speech is dropped via `ui.cancel_voice_turn()`. Printable keys the watcher inevitably consumes are stashed and fed to the next `prompt_async(default=...)` as type-ahead — typing the next message during a turn still works. On Unix, **Ctrl+C during a turn** goes through a loop-level SIGINT handler (`make_sigint_handler` + `InterruptPolicy` in interrupt.py): the first press cancels the turn task, a second within 2 s force-quits via `os._exit(130)`. The double press exists because a turn blocked in `asyncio.to_thread` (MPS inference, whisper finalize) cannot actually be cancelled — asyncio defers the cancellation until the executor thread ends — which once made Ctrl+C look dead and pushed a user to Ctrl+Z, suspending the process with the microphone still attached; only process death reliably frees it. At the prompt, prompt_toolkit's raw mode handles Ctrl+C itself (→ `/quit`).

Turns render **live**: `process_user_turn` opens `ChatUI.turn_stream()` (`src/ui/stream.py`) — one rich Live region with a phase stopwatch ("thinking… Ns" / "running tools… Ns"), tool calls and tool results printed the moment they happen (results carry their duration), a dim "thought for Ns" line before each action, and a tail of the model's streamed text. Message ids printed live are handed to `print_response(skip_ids=...)` so nothing prints twice; `TurnStream` dedups by message id and swallows its own errors (display must never break a turn). The stream is driven by `ask_agent(on_message=..., on_token=...)`: with a callback set, `LLMClient._stream_agent` switches `ainvoke` to `astream(stream_mode=["updates", "values", "messages"])` — `updates` yields new messages per node, `messages` yields model tokens (filtered to `langgraph_node == "model"` so the summarizer's calls stay silent), and the last `values` chunk is the final state. `build_client_kwargs` sets `stream_usage=True` for openai/azure so streamed turns keep `usage_metadata` and the footer stays populated.

`main()` also warms the NVIDIA LocateAnything vision model at startup (`preload_vision_model` → `warm_up_computer()` from `src/llm/tools/computer/tool.py`, which calls the locator's `load()`); failures are logged and the locator falls back to lazy loading on first use. The preload runs on a **daemon `threading.Thread`, never `asyncio.to_thread`** — the default executor's workers are non-daemon, and /quit during a first-run model download used to hang the interpreter in `concurrent.futures`' atexit join. All model warm-ups (vision, voice ASR/TTS) report progress via `ChatUI.set_model_status(name, state, detail=None)`, rendered live at the right of the prompt (`_rprompt_status`: `⏳ name Ns` → `✓ name` lingering a few seconds → gone; `✗ name` on failure; `detail` carries first-run download progress like `↓ 1.2/6.4 GB 19%` and updates within the same state keep the stopwatch start); the `PromptSession` has `refresh_interval=0.5`, so these stopwatches and the voice recording status tick without any thread invalidating the app. Download progress flows through `src/utils/downloads.py`: the warm-up wrapper opens `reporting_progress(callback)` (per-thread, like `silenced()`), and `download_hf_model` — used by both the locator and the whisper provider — fetches the hub file list itself and downloads **sequentially with `hf_hub_download` on the calling daemon thread** (deliberately not `snapshot_download`, whose internal `thread_map` pool has the same non-daemon exit-hang; byte progress comes from watching the repo cache dir grow, which stays correct under both plain-HTTP and hf_xet transports; a cached snapshot is trusted only when the caller's `required_files` are present, because an interrupted `snapshot_download` writes the ref before the weights). Silero reports the same way from its httpx byte loop. Tests patch `src.main.preload_vision_model` so the suite never loads the model. Because these loads run while the prompt is live, the loaders wrap themselves in `silenced()` (`src/utils/silence.py`) — `sys.stdout`/`sys.stderr` are replaced once with thread-routing proxies, so the loading thread's transformers warnings, remote-code prints, and progress bars are dropped while the UI thread keeps printing normally (`quiet_transformers()` additionally kills transformers' logger and progress bars). Never use `redirect_stdout` for this — it is process-global and would eat the UI's output. C-level noise that `silenced()` cannot catch — the objc duplicate-class warnings when `av` (faster-whisper) and `cv2` (vision remote code) both load their bundled libavdevice on macOS — is muted by `suppress_native_stderr()` (same module): a refcounted dup2 over fd 2, kept to the model-construction window only, never around a download. The redirect target is `logs.native.log`, NOT /dev/null — when a native library aborts the process its last words are the only clue, and they must stay on disk (a Tk abort once looked like a clean exit because of a devnull redirect; macOS crash reports in `~/Library/Logs/DiagnosticReports/` are the other place to look).

After each successful turn `report_usage` prints a footer — a colored context progress bar (`ChatUI._context_bar`, green → yellow → red by fill), turn tokens, dollar cost, wall-clock turn time (`took Ns`, measured in `process_user_turn`; the session total accumulates in `SessionUsage.duration`), tool-call counts, session totals. The tools segment shows direct model tool calls plus tools invoked inside `run_tools` scripts; the latter are counted per run by a ContextVar counter (`counting_script_calls` in `src/llm/statistics/script_calls.py`), reported in the run_tools result JSON as `tool_calls`, and parsed back out of new ToolMessages by `turn_usage_from_messages`. Token counts come from `usage_metadata` on the turn's new AI messages (`src/llm/statistics/usage.py`; the `TurnUsage` record lives in `src/llm/types.py`, small extractors/formatters in `src/llm/utils.py`); history returned in the response is excluded by message id, and the context figure is the **last** call's input+output (its input already contains the whole history). Context lengths and per-token USD prices come from the public OpenRouter API via `OpenRouterCatalog` (`src/llm/providers/openrouter.py`) — fetched in a background task at startup, cached for the session, with a failure cooldown so an offline machine isn't re-polled every turn, and injectable `fetch_payload`/`clock` seams for tests. `ChatUI.handle_command` is synchronous and delegates to `CommandHandler` (`src/ui/commands.py` — every slash command lives there); the catalog is handed to the UI as a plain dict via `set_model_catalog()`. `/models [query]` renders context + $/M pricing (search covers the whole catalog but offers only tool-capable models); `/model <name> [effort]` switches by exact or unique-partial match over the curated list plus the catalog — models whose `supported_parameters` positively lack `tools` are refused, unknown ones (empty capability list, or catalog unavailable) are allowed. `/effort` and `/temperature` set per-session `ChatUI.reasoning_effort`/`ChatUI.temperature`, which `main()` passes into `process_user_turn` → `right_coding_agent` → `ask_agent` on every turn; both commands refuse values the catalog positively marks unsupported for the current model, and with no argument they explain what "default" means (`ChatUI.settings_line()` shows the model's own default temperature when the catalog publishes `default_parameters`). Commands autocomplete while typing via `CommandCompleter` (`src/ui/completer.py`, wired into the `PromptSession`): command names, tool-capable model ids (reusing `CommandHandler.catalog_matches`, so `:batch` and tool-less models are never offered), effort and log levels.

Completion sound: `process_user_turn` calls `ui.notify_done()` when a turn finishes; playback (`src/ui/sound.py`) of `assets/sounds/done.mp3` is toggled by `/sound [on|off]` (`ChatUI.sound_enabled`) and must be **instant and non-blocking**: on Windows it goes in-process through winmm MCI (`mciSendStringW`, mp3-capable) — do NOT switch it to a spawned PowerShell/WPF player, whose seconds-long cold start makes the sound arrive late and the toggle look broken; macOS/Linux use fire-and-forget `afplay`/mpg123/ffplay/cvlc processes. Failures only log, never block the loop.

Clipboard images: `/paste` (and a Ctrl+V key binding, in terminals that forward the key instead of pasting themselves) reads the clipboard via `src/ui/clipboard.py` (`PIL.ImageGrab.grabclipboard` — Windows/macOS native, Linux via xclip/wl-paste; also handles copied image *files*), encodes to JPEG capped at 1568px, and queues it in `ChatUI.pending_images`. The main loop calls `ChatUI.take_user_content(text)` before each turn — with images pending it returns `image_url` content blocks for the `HumanMessage` (the shape providers accept) and clears the queue; `/clear` drops pending images too. `MessageLogMiddleware.scrub_text` already strips the data URIs from logs. Usage reporting must never break a finished turn — `report_usage` swallows and logs its own failures.

`src/llm/client.py` — `LLMClient` owns provider configuration and the resilience loop: for each configured `LLMProvider` (see `src/llm/types.py`) it retries `num_retries` times with a cooldown, then fails over to the next provider. `ask_agent()` builds a fresh LangChain `create_agent` per call (model + tools + middleware + optional `response_format`). Passing a `thread_id` turns on the `MemorySaver` checkpointer and interrupt support: an interrupted run comes back with `__interrupted__` set, and `resume_agent()` continues it via `Command(resume=...)` using a per-thread agent cache.

`src/llm/agents.py` — `Agents(LLMClient)` defines concrete agents. `right_coding_agent()` composes:
- the system prompt from `src/config/prompts.py`;
- `META_TOOLS` — the agent's **entire** tool surface (see "Meta tools" below); there are no direct file, shell, web, or screen tools;
- `AttachedImagesMiddleware` (surfaces tool screenshots as vision messages, see "Meta tools");
- `SummarizationMiddleware` (summarizes history past 40k tokens using a small model);
- `MessageLogMiddleware` (`src/llm/middlewares/message_log.py`) — logs model traffic to `logs.log` as self-describing JSON lines: `{"event": "model_request", ...}` with the full message list before every call, and `{"event": "model_response", ...}` with the returned AIMessage **including its `response_metadata` (finish_reason)** after it — that's how empty/aborted completions get diagnosed. Registered **last** so it sees the message list exactly as the model does. Its `scrub_text` replaces data URIs and long base64 runs with `<... stripped, N chars>` placeholders and truncates remaining long text; the terminal UI reuses it for tool-result previews. Tests inject `emit=` to capture lines.

Models are addressed by provider-prefixed name (e.g. `google/gemini-3.7-flash`) and routed through one OpenAI-compatible endpoint (`LLM_API_BASE`); the startup model comes from the optional `LLM_DEFAULT_MODEL` env var (`settings.llm_default_model`, defaulted in `src/config/settings.py`), which seeds `available_models` at the top of `src/main.py`.

To add an agent: add a method on `Agents` calling `self.ask_agent()`. To add a tool: create a subpackage under `src/llm/tools/` following the `parser/` / `computer/` pattern — `service.py` with the class doing the real work, an optional `utils.py`, and `tool.py` with the `@tool(parse_docstring=True)` async functions — then register the tools in the default registry in `src/llm/tools/meta/defaults.py: get_registry()`. Tool docstrings become the LLM-facing schema, and tools catch their own exceptions and return the error as a string rather than raising.

### Meta tools (tool discovery + scripted orchestration)

The agent does **not** see individual tool schemas. The whole meta layer lives in `src/llm/tools/meta/`: `tool.py` exposes exactly three tools — `search_tools` (keyword search over the registry), `get_tool` (full contracts of one or more tools per call; takes a name list, tolerates a loose comma/space-separated string), and `run_tools` (execute a Python-subset script) — so the context cost stays flat no matter how many tools are registered. Real tools live in a `ToolRegistry` (`meta/registry.py`; the process-wide default — `web_fetch`/`web_search`, the `files/` and `shell/` coding tools, and the `screen_*` family — is built in `meta/defaults.py`) and are called *by bare name from inside `run_tools` scripts*, executed by the sandboxed tree-walking interpreter in `meta/sandbox/` (`Interpreter`): whitelisted AST nodes/builtins/methods only, no imports or dunder access, op/sleep/wall-clock/memory budgets, `sleep()` for token-free polling and a `parallel(...)` special form for concurrent tool calls. The sandbox package is layered — `interpreter.py` (execution core), `policy.py` (AST/method whitelists), `limits.py` (budgets), `guards.py` (allocation guards), `builtins.py` (script builtins), `python -m src.llm.tools.meta.sandbox` (demo) — and knows nothing about LangChain or the registry; it executes scripts against a plain name→async-callable table. `meta/__init__.py` deliberately re-exports nothing (an eager import of `tool.py` there would close a circular-import loop through `defaults.py` and the concrete tool packages); the public names come from `src/llm/tools/__init__.py`.

Integration details that matter when changing this layer:
- `ToolRegistry` adapts LangChain tools to plain async callables (`_as_script_callable`) — positional args are mapped onto schema field order, then routed through `ainvoke` so argument validation stays in the path.
- The interpreter resolves names as scope → builtins → tools, so a tool named like a builtin would be silently unreachable; `register()` rejects `RESERVED_SCRIPT_NAMES` for that reason.
- `run_tools` returns JSON `{result, logs, error}` clipped to `MAX_RESULT_CHARS`; a fresh `Interpreter` is built per call so concurrent runs don't share mutable state.
- `set_registry()` (in `defaults.py`) is the test seam (mirrors `set_computer()`); tests install a registry of fake tools and never touch the real desktop or network. The `run_tools` docstring is the language contract shown to the model — keep it in sync with what `Interpreter._validate`/`_eval` and the sandbox `policy.py` whitelists actually allow.

**Screenshots and vision.** Base64 in a tool's text result is invisible to the model — providers only read images from `image_url` content blocks in user-role messages, and OpenAI-compatible APIs don't accept images inside tool messages. The pipeline spans two modules: the tool-side channel is `src/llm/tools/meta/attachments.py` — tools call `attach_image()` into a ContextVar bucket that `run_tools` opens per call (`collecting_images()`); the images leave the run as the ToolMessage's `artifact` (kept in graph state, never sent to the provider); then `AttachedImagesMiddleware.before_model` (`src/llm/middlewares/attachments.py`) appends one HumanMessage of data-URI `image_url` blocks for the latest tool round (idempotent via an `attached_images` marker in `additional_kwargs`, so retries don't duplicate). `screen_screenshot` and `screen_locate(return_screen=True)` feed it; attachments are capped at `MAX_ATTACHED_IMAGES` per run with the drop count reported in the run_tools JSON. When no channel is open (library use outside the agent), the screen tools fall back to raw base64 in their text result.

### Computer use

`src/llm/tools/computer/` gives the agent eyes and hands on the desktop. `service.py` — the `ComputerUse` facade — combines perception (screenshot → natural-language locate → boxes) with control (mouse, keyboard, clipboard) and a "show, don't touch" marker overlay (`mark_object` outlines an element and shows a tooltip instead of clicking).

Every OS-facing dependency is an injected backend behind a protocol (`types.py`); the implementations live in `platforms/`, selected lazily by the factory in `platforms/__init__.py` (`default_screen`/`default_pointer`/`default_clipboard`, `enable_dpi_awareness`, `foreground_window`/`focus_window`). `platforms/windows/` is native (screen.py: DPI + capture; pointer.py: SendInput mouse+keyboard; clipboard.py: Win32; focus.py: window focus); `platforms/portable/` covers macOS/Linux via pynput (input incl. the same `ctrl+c`-style key language), mss (capture), pyperclip (clipboard), and CLI-driven window focus (`focus.py`: AppleScript/`osascript` on macOS, `wmctrl` + `xdotool` on Linux; subprocess calls take a `runner` seam for tests). **Never import `platforms.windows` modules outside the factory or Windows-only tests**: `ctypes.wintypes` fails to import on other OSes, and `computer/__init__.py` deliberately re-exports only cross-platform names (test_platforms.py enforces this). `locator.py` (the nvidia/LocateAnything-3B runtime — the **only** module that imports torch, loaded lazily on first locate) picks cuda → mps → cpu automatically; `overlay.py` (Tk) is cross-platform except win32 click-through. `fakes.py` provides `StaticScreen`, `RecordingPointer`, `ScriptedLocator`, and `MemoryClipboard`, which is how every test runs without a desktop — construct `ComputerUse(locator=..., screen=..., pointer=..., overlay=NullOverlay(), ...)` with fakes. Detection, parsing, and annotation are platform-independent.

Two behaviors worth knowing before touching locating code:
- **Two-pass refinement:** inference downscales the screen to 768px, so small targets drift by ~100px. `locate_object` does a coarse full-screen pass, then re-locates inside a native-resolution crop around each small hit (`detection.py: needs_refinement`). Passing `region=` skips straight to native resolution when the neighbourhood is known.
- **Screenshot-keyed cache:** results are cached per (description, region, mode, refine) and reused while the screen is byte-identical — or, within `cache_ttl` (15 s) of the last real inference, merely near-identical at the same resolution (`screen_thumbnail`/`screens_roughly_equal` in detection.py: 64-px grayscale thumbs, mean-diff threshold). A live desktop never stays byte-identical (menu-bar clock, terminal spinners), and on CPU/MPS a locate costs many seconds, so locate-then-mark must not pay twice; big changes (scroll, moved window, resolution change) still miss, and the TTL runs from the last inference so fuzzy hits cannot chain forever. Decoding is greedy on purpose — sampling gave nondeterministic boxes.
- **Click settle:** a positioned click sleeps `click_settle` (0.2 s) between the move and the press — macOS hover-revealed controls (PiP close buttons, fading toolbars) ignore a press fired the instant the pointer lands ("it moved the mouse but did not click"). A click at the current position does not wait.
- **Single-flight load:** `LocateAnythingLocator.load()` is guarded by a lock — the startup preload and the first screen tool once raced and loaded the 7 GB model TWICE, which on a 16 GB Mac swap-stormed a one-minute load into many minutes. The second caller must wait, never load again.
- **One tool to find and show:** there is no separate mark tool — marking is part of `screen_locate(mark=True, note=..., title=..., match=...)` (a bare `note` implies `mark`), so find-and-show costs ONE inference, never two. Both `screen_locate` and `screen_click` take `region` — the same 3×3 grid names results are reported with ("top-right"), edge strips ("top-bar", "bottom-bar", "left-bar", "right-bar"; `parse_region` in detection.py), or "l,t,r,b" pixels — which shrinks the coarse pass dramatically (a menu-bar strip is ~20× fewer image tokens than the full screen). `VISION_QUANTIZATION=int8` (settings) quantizes the locator weights via optimum-quanto before the device move — halves the ~7 GB footprint, the difference between paging and not on a 16 GB Mac. Real-model integration tests live in `tests/test_vision_integration.py`, opt-in via `RUN_VISION_TESTS=1` (they print timings and honour `VISION_QUANTIZATION`, so runs double as benchmarks).
- **Ambiguity guard:** the mark and click paths (`src/llm/tools/computer/tool.py: _resolve_match`) act only on a unique match — several matches return the candidate list (with `position_label` coarse positions from `detection.py`) and require a refined description or `match=<n>`; the cache makes the follow-up pick deterministic. The tools' `description` docstrings teach the model to write anchored queries ("the URL address bar at the very top of the browser window", never "the input field"). Note: langchain's Google-docstring parser treats any `Args:` continuation line containing a colon as a new argument — use dashes in those lines.

`src/llm/tools/computer/tool.py` exposes this to the agent as `screen_*` LangChain tools over a process-wide `ComputerUse` singleton (`get_computer()` / `set_computer()` — the latter is the test/headless seam). Sync `ComputerUse` calls are wrapped in `asyncio.to_thread`. `cli.py` holds the interactive locator REPL loop (`run_interactive_loop`) used for manual testing of the locator.

### Voice layer

`src/voice/` is the push-to-talk speech layer, deliberately shaped like the LLM layer: `VoiceProvider` (`types.py`) names a provider the way `LLMProvider` does, and the factories in `providers/__init__.py` (`build_transcriber` / `build_speaker`) map it onto implementations behind the `Transcriber`/`Speaker` protocols — `local` today, `fish`/`elevenlabs` planned as cloud adapters (their APIs are structurally different — Fish: Bearer auth + `model` header + `reference_id` in body; ElevenLabs: `xi-api-key` header + voice in the URL — so unification happens at our protocols and the keys stay separate: `FISH_AUDIO_API_KEY` / `ELEVENLABS_API_KEY`; all `voice_*`/TTS settings live in `src/config/settings.py` with safe defaults). Heavy deps (torch, faster-whisper, pynput, sounddevice) are imported lazily, so importing `src.voice` is cheap.

- `providers/whisper.py` — faster-whisper ASR with CUDA→CPU-int8 fallback; on Windows it must expose torch's bundled cuDNN DLLs to ctranslate2 first (`_add_torch_cuda_dlls` — do not remove). `WhisperSession` is the latency trick: incremental passes during recording commit every returned segment except the last and advance the window past them, so `finalize` transcribes only the small tail — release-to-text stays ~0.3–0.6s regardless of utterance length (measured live). `beam_size=5` by default because greedy decoding garbles mixed Russian/English speech; `hotwords` biases known tech terms toward Latin script.
- `providers/silero.py` — Silero TTS on CPU on purpose (the GPU is busy with the vision model and whisper; Silero is faster than real time on CPU), **bilingual by sentence**: `detect_language` routes any-Cyrillic → v4_ru (speaker from `VOICE_TTS_SPEAKER`) and pure-Latin → v3_en (`VOICE_TTS_SPEAKER_EN`, en_0…en_117) — an English sentence through the Russian model comes out as ~0.3 s of noise ("voice spoke for a millisecond"), and v3_en rejects the Russian-only `put_accent`/`put_yo` options. Each model (~40–60 MB) downloads into `models/silero/` on first use. Chosen as the local default after evaluating emotional models (Chatterbox Multilingual — MIT, ru; OpenAudio S1-mini — ru but CC-BY-NC): those arrive later as extra providers through `build_speaker`, nothing else changes.
- `audio.py` — `MicrophoneRecorder` (thread-safe `snapshot()` while recording) and `AudioPlayer` (block-wise playback interruptible via `stop()` — that's what makes barge-in cut speech within ~0.1s). `hotkey.py` — global toggle with a three-tier backend chain, most robust first. On Windows the primary is `rawinput.py`: a hidden message-only window registered with `RIDEV_INPUTSINK` receives session-wide WM_INPUT (how Wispr-Flow-class tools do push-to-talk) — no low-level hook to lose (pynput's hook has a ~300 ms callback timeout and Windows silently removed it under game load while our torch/whisper threads held the GIL, which is why the hotkey "randomly" died in games) and raw-input games can't starve it; ctypes calls there MUST keep their explicit argtypes — without them 64-bit handles get squeezed into c_int (that bug shipped and was caught by the SendInput smoke test `testscripts/test_hotkey_check.py`, which injects right Alt and asserts the sink fires). Fallback two: `KeyStatePoller` polling `GetAsyncKeyState` every 30 ms; fallback three: pynput (Linux, exotic keys/characters). **On macOS BOTH backends run at once** (`DualListener`): the `KeyStatePoller` over `Quartz.CGEventSourceKeyState` (`DARWIN_KEYCODES`/`darwin_state_reader`, both event-source states consulted) AND a pynput tap, deduped by `HotkeyListener._fire`'s 250 ms debounce. Neither alone is trustworthy: the tap is silently disabled by `kCGEventTapDisabledByTimeout` when whisper's CPU spikes starve the callback (observed live as "the stop press never arrived, the pill stayed on listening forever"; pynput never re-enables it), while key-state polling is blind in some terminals' TCC contexts (observed live in kitty: the tap delivered for weeks, the poller never saw one press). The macOS path preflights **both** Accessibility (`AXIsProcessTrusted`) and Input Monitoring (`CGPreflightListenEventAccess`) via `macos_input_access` — each raises its system permission dialog once when missing — and raises `PermissionError` with instructions instead of starting an untrusted event tap: with either permission missing the tap starts without any error and silently receives nothing ("the key does nothing"), and an untrusted tap additionally prints "This process is not trusted!" over the prompt; `main()` shows the message via `print_warning`. `describe_hotkey` gives keys their macOS names in the welcome line (`alt_r (right Option ⌥)`) because "alt_r" alone reads as the wrong key there. Right Alt default; `resolve_vk`, `normalize_vk`, and `parse_hotkey` all treat AltGr as right Alt because some layouts report it that way. `VoiceController` logs every PTT stage (backend chosen, recording started, audio/finalize seconds, text length) — check logs.log first when "the key doesn't work". `utils.SentenceBuffer` — token stream → complete sentences, so TTS starts speaking while the model is still generating.
- Everything takes injectable factories/loaders; `tests/test_voice.py` covers the layer with fakes and never touches microphone, speakers, models, or a real key listener. Validation sandboxes (mic/latency/quality experiments) live in `testscripts/` (gitignored).

**REPL wiring** (`src/ui/voice.py`): `VoiceController` glues the layer to the chat loop, and its two switches are deliberately independent — **push-to-talk is always on** (`start_input()` runs at REPL startup in `main()`, warming the ASR model in the background; a failure only prints a warning), while `/voice` flips only `speak_replies` (spoken answers + the TTS prompt suffix; `ChatUI.voice_active` reads it). One hotkey press starts recording (a worker steps the incremental session; the prompt's `rprompt` shows a stopwatch + draft tail; each recording gets its OWN stop Event so a worker still finishing a slow step can never latch onto the next recording), the next press gives feedback FIRST and transcribes AFTER: `_finish_recording` instantly flips the pill to "syncing", clears the stopwatch, grabs the audio buffer, and returns — the slow parts (waiting out the worker's in-flight whisper step, then `finalize`, seconds each on CPU) run on a finalize thread serialized by `_finalize_lock`, which then delivers the transcript — typed into the active prompt's buffer and accepted with `validate_and_handle()` (a programmatic Enter, so the user sees the recognized text, it stays in scrollback and input history, and typed-but-unsent text is kept in front of it) via `call_soon_threadsafe`, or parked in `take_pending_text()` (consumed by `ChatUI.get_input`) when no prompt is up — and plays `done.mp3` as a sent-confirmation (`_play_sent_cue`, gated by `sound_enabled`): PTT works with any window focused, so silence after the second press must mean "nothing was recognized", not "maybe it sent". Spoken replies: `turn_callbacks` in `src/main.py` tees the turn's `on_token` into `VoiceController.feed_token` → `SentenceBuffer` → `SpeakableFilter` (drops fenced code even across sentences, strips inline markdown) → a speech-worker queue synthesizing and playing sentence-by-sentence while the model still streams; `finish_turn()` (called via `ui.finish_voice_turn()` on every turn exit path) flushes the tail and resets fence state. Pressing the hotkey during speech is barge-in: queue drained, playback interrupted, recording starts. With spoken replies on, `process_user_turn` passes `voice_mode=True` → `Prompts.coding_system` appends `voice_mode_suffix` (answer in plain speakable prose, no markdown/code) — keep `evaluation/direct_agent.py` doing the same; `notify_done` skips the completion sound because speech is the signal. Everything is per-thread-safe by construction: listener thread → `toggle()`, workers own their loops, the asyncio loop only sees `call_soon_threadsafe` callbacks, and every voice path logs-and-swallows its own failures.

**On-screen status overlay** (`src/ui/overlay.py`, `StatusOverlay`): one transparent click-through Tk window (same technique and thread/queue pattern as the computer-use marker overlay) drawing two layers over everything, games included. The **voice pill** at the bottom of the screen animates level bars while recording and pulsing dots from send until the reply lands — `VoiceController._set_overlay_voice` drives listening → syncing → hidden (hidden also on empty transcript, cancel, `/voice` off is irrelevant — the pill follows push-to-talk, not spoken replies). The **computer border** is a breathing accent frame meaning "the AI is driving your desktop — hands off": every `screen_*` tool calls `_ping_activity()` (`set_activity_listener` in `computer/tool.py` is the UI hook, wired in `main()` to `get_status_overlay().ping_computer()`), and the frame fades ~3 s after the last ping. `_apply`/`computer_active`/`blend` are pure and unit-tested; the animation loop runs at ~15 fps only while something is visible, and the window is withdrawn when idle. `set_status_overlay()` is the test seam; visuals are verified by `testscripts/test_status_overlay_check.py` (screenshot pixel checks per state). **Tk on a background thread is forbidden on macOS**: AppKit only allows window creation on the main thread, and a Tk root on the overlay thread raises NSException and **aborts the whole process** (SIGABRT in `TkMacOSXMakeRealWindowExist` — this shipped as "the app closes after the first voice turn on macOS"). The status overlay therefore has two backends behind the same API (`tk_thread_supported`, duplicated in `src/ui/overlay.py` so it stays runnable as a script): the Tk-thread window on Windows/Linux, and on macOS a **child process** — `StatusOverlay._spawn_child` launches `python src/ui/overlay.py` (stdlib+loguru only at module level, so it imports without `src.*` or `.env`), which puts Tk on the child's main thread, reads JSON command lines from stdin (`encode_command`/`decode_command`; EOF = parent died = shut down), fixes uv-python's Tcl discovery via `_ensure_tcl_env`, and draws a fullscreen window with true transparency (`-transparent` + `systemTransparent`), AppKit click-through and no Dock icon; `VoiceController.start_input` calls `overlay.prewarm()` so the ~1s child boot happens at REPL startup, not on the first hotkey press. On macOS the voice indicator is a **notch island** instead of the bottom pill: an opaque (`ISLAND_ALPHA`) black rounded-bottom slab popping out of the physical notch at top center (`island_geometry`/`island_progress` with ease-out both ways; notch width from `NSScreen.safeAreaInsets` + auxiliary areas, `NOTCH_FALLBACK_WIDTH` on notch-less displays; content draws below `NOTCH_BOTTOM` because the notch itself is black glass; `_has_content` keeps the window alive through the retract animation). The child renders all three layers — island/pill, border, and element markers (`screen_locate(mark=True)`) (`ComputerUse` picks its marker backend via `default_overlay()`: `TkOverlay` where Tk threads are legal, else `ChildMarkerOverlay`, which serializes `Marker` → wire dict into the same child; marker coordinates arrive in capture pixels and the child divides by `NSScreen.backingScaleFactor` because retina capture is 2× the Tk point grid). If AppKit is unavailable the child cannot guarantee click-through and falls back to the small pill-only window (fullscreen without click-through would block the whole desktop); the marker geometry helpers are canonical in `computer/overlay.py` with script-safe copies in `src/ui/overlay.py`, kept in sync by a unit test. `/check` (`CommandHandler._run_check` → `src/utils/permissions.py`) probes all four macOS permissions (Accessibility, Input Monitoring, Screen Recording, Microphone) and raises every missing consent dialog at once — each fails silently when denied, so this is the one-stop first-run setup command.

### Other pieces

- `src/llm/tools/parser/` — the web: `service.py` holds `WebParser` (httpx + BeautifulSoup fetch, HTML→Markdown, DuckDuckGo search via `ddgs`), `utils.py` its text helpers, `tool.py` the `web_fetch` (URL→Markdown) and `web_search` (query→results) tools. Note the rename: the old `web_search(url)` fetcher is now `web_fetch`.
- `src/llm/tools/files/` and `src/llm/tools/shell/` — the coding tools (`read_file`, `write_file`, `edit_file`, `glob_files`, `grep_files`; `bash`). `FileService` is pure Python (no ripgrep dependency), caps every result, and skips `.git`/`.venv`-style directories; `CommandRunner` prefers a real bash (Git Bash on Windows), is stateless between calls, and reports non-zero exits as an `[exit code N]` prefix instead of raising.
- `evaluation/` — the architecture-comparison harness, kept out of `src/` on purpose: `DirectAgents` overrides `right_coding_agent` with the same middlewares but `DIRECT_TOOLS` (every registry tool wrapped for direct model invocation, with the image-attachment channel opened per call) instead of the meta tools, and `evaluation/main.py` is a parallel REPL (`uv run python -m evaluation.main`) reusing `src.main`'s turn loop pieces. Keep it behaviorally in sync with `Agents.right_coding_agent` when changing middlewares, or the comparison stops being fair.
- `docs/superpowers/plans/` and `docs/superpowers/specs/` — dated design docs for features in progress; check there for intent before reworking the screen-locator behavior.
